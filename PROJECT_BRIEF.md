# NiaGuide Africa — Product Brief

## 1. Product identity

**Product name:** NiaGuide Africa

**Academic project title:** Design and Evaluation of a Source-Grounded AI Platform for Career Guidance and Purpose Development among Nigerian University Students

**Tagline:** Grounded guidance. African knowledge. Clear sources.

**One-sentence description:** NiaGuide Africa is a web platform that helps Nigerian university students ask career and personal-development questions and receive AI-generated answers based only on approved materials from African leaders and experts, with visible sources for every supported answer.

## 2. Target users

### Primary users

Nigerian university students aged 18–25 who need clear and trustworthy guidance about careers, self-discovery, leadership, skills, and purposeful development.

### Secondary users

- Administrators who create expert profiles and manage approved source collections.
- Researchers who review anonymous usage, feedback, and evaluation results.
- African experts or their authorised representatives who approve profiles and source materials.

## 3. Main problem

Many Nigerian university students want guidance from experienced African leaders and experts, but they may not have direct access to these people. Useful advice is often spread across videos, speeches, interviews, books, articles, and social media. Ordinary search can take time and may not explain which passage answers a question. General chatbots may provide confident answers without showing that the selected expert actually expressed the idea.

NiaGuide Africa will test whether a source-grounded assistant can make approved African expert knowledge easier to explore without pretending that the AI is the expert.

## 4. Core product promise

The platform must retrieve relevant passages before generating an answer. A supported answer must show its sources. If the system cannot find enough evidence, it must say so instead of guessing.

## 5. MVP scope

### Student features

1. View a landing page that explains the platform and its limitations.
2. Browse expert profile cards.
3. Open an expert profile and review the expert's topics, biography, source count, and disclosure.
4. Ask a question after selecting an expert.
5. Receive an answer grounded in that expert's approved collection.
6. See numbered source markers and open the supporting passages or source links.
7. Receive a clear limitation message when there is not enough evidence.
8. Rate the answer and report a problem.

### Administrator features

1. Sign in to a protected administrator area.
2. Create, edit, enable, or disable an expert profile.
3. Add approved documents and their metadata.
4. Process documents into searchable passages and embeddings.
5. Review feedback and reported answers.

### Initial demonstration scope

- Display three expert cards.
- Make one expert collection fully functional from question to cited answer.
- Mark the other two profiles as **Coming soon**.
- Demonstrate one supported question and one question that triggers the insufficient-evidence message.

The later capstone may expand to about twenty expert collections. The research survey may target up to 200 students. These larger numbers do not need to be completed for the initial software demonstration.

## 6. Features explicitly excluded from the MVP

- Training or fine-tuning a new machine-learning model.
- Claiming that the AI is the selected expert.
- Writing in the first person as though the expert is speaking live.
- Voice cloning, face cloning, avatars, or deepfakes.
- Live mentor matching, direct messaging, or video calls.
- Open document uploads by ordinary users.
- Automatic web scraping without source review.
- Advice for users under 18 during the research pilot.
- Medical, legal, financial, or emergency advice.
- Payments, subscriptions, advertisements, or a marketplace.
- Native Android or iOS applications.
- Support for every African country, language, or profession in the MVP.

## 7. Required disclosure text

Show this message above or below every generated answer:

> This answer was generated by AI from the approved sources listed below. It is not a direct statement from the selected expert and it does not mean that the expert personally reviewed this question. Please check the sources before making an important decision.

Show this shorter label near the answer heading:

> AI-generated, source-grounded answer

## 8. Insufficient-evidence message

Use this exact default message:

> I could not find enough information in this expert's approved sources to answer your question reliably. Try asking a more specific question, or choose another expert. I will not guess or speak on the expert's behalf.

## 9. Pilot expert plan

### Recommended first expert

**Provisional expert:** Joyce Daniels

**Why this is recommended:** The project owner already has a professional relationship with Joyce Daniels and may be able to request written permission and approved material quickly. This is safer and more practical than scraping a famous person's content without approval.

**Provisional profile:**

> Joyce Daniels is a Nigerian communication and leadership-development professional. Her collection on NiaGuide Africa focuses on public speaking, confidence, professional communication, leadership, and personal growth.

This profile is a draft. Joyce Daniels or her authorised representative must review and approve it before public release.

**Expert disclosure:**

> This is an AI knowledge assistant built from materials approved for this pilot. It is not Joyce Daniels, does not speak for her, and does not provide a live conversation with her. Each answer should be checked against the displayed sources.

### Materials to request from the first expert

Ask for written permission to use:

1. One approved biography of about 100–150 words.
2. One to three public or privately supplied articles, speeches, transcripts, or teaching notes.
3. Answers to 10–15 common questions about career growth, confidence, communication, and purpose.
4. A list of topics the assistant may discuss.
5. A list of topics the assistant must not discuss.
6. Permission to display the expert's name, photograph, biography, document titles, and source links in a university prototype.

Do not upload paid courses, unpublished books, client information, or confidential material unless the owner gives clear written permission.

### Two visible but inactive profiles

The demonstration may show two placeholder expert cards labelled **Coming soon**. Do not upload or generate answers from their content until source rights and profile wording have been reviewed.

## 10. Technology decisions

| Part | Decision | Purpose |
|---|---|---|
| Web application | Next.js with TypeScript | Frontend pages and server routes in one project |
| Styling | Tailwind CSS | Responsive and consistent interface |
| Database | Supabase Postgres | Expert, document, passage, query, answer, citation, and feedback records |
| Authentication | Supabase Auth | Protected administrator access |
| File storage | Supabase Storage | Approved source files |
| Vector search | pgvector in Supabase | Find passages related to a student's question |
| Answer model | OpenAI `gpt-6-luna` | Low-cost answer generation for a focused prototype |
| Embeddings | OpenAI `text-embedding-3-small` | Turn questions and passages into vectors for similarity search |
| Hosting | Vercel | Deploy the Next.js application |
| Source control | GitHub | Version history and assignment submission |

All API calls must run on the server. Secret keys must never be placed in browser code or committed to GitHub.

## 11. Main pages

1. `/` — Landing page
2. `/experts` — Expert directory
3. `/experts/[slug]` — Expert profile
4. `/ask/[slug]` — Question and answer workspace
5. `/about` — How source grounding, disclosures, and limitations work
6. `/admin` — Protected administrator dashboard
7. `/admin/experts` — Expert management
8. `/admin/sources` — Source collection management
9. `/admin/reports` — Feedback and report review

## 12. Initial demonstration acceptance criteria

The initial version is ready when:

- The repository has a clear README and setup instructions.
- The application runs locally without build errors.
- Navigation works on desktop and mobile widths.
- At least the landing page, expert directory, expert profile, ask page, about page, and admin dashboard exist.
- One approved expert collection can produce a cited answer.
- A weakly supported question produces the insufficient-evidence message.
- Sources display a title, link, and supporting passage.
- Feedback can be saved.
- The database schema and server endpoint are visible in the repository.
- Environment variables are documented in `.env.example`, but real secrets are absent.
- The application is deployed and has a working public URL.
- The README includes screenshots, architecture summary, deployment plan, and repository link.
- A 5–10 minute demonstration can show the main flow without relying on hidden manual steps.
