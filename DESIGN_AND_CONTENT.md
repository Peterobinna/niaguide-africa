# NiaGuide Africa — Design and Content Guide

## 1. Design direction

The interface should feel trustworthy, calm, youthful, African, and academic. It should not look like a science-fiction chatbot. Sources and limitations should be as visible as the answer.

Use generous spacing, short paragraphs, large readable text, clear buttons, simple cards, and a strong mobile layout.

## 2. Colour palette

| Role | Colour | Hex |
|---|---|---|
| Primary | Deep navy | `#0B1F3A` |
| Interactive | Royal blue | `#1F5EFF` |
| Accent | Warm gold | `#F5B942` |
| Page background | Soft cloud | `#F7F9FC` |
| Card background | White | `#FFFFFF` |
| Main text | Ink | `#1B2430` |
| Muted text | Slate | `#667085` |
| Success | Green | `#168A5B` |
| Warning | Amber | `#B7791F` |
| Error | Red | `#C83E4D` |
| Border | Light grey | `#DDE3EA` |

Check colour contrast for normal text and interactive states.

## 3. Typography

- Use **Inter** for headings, body text, buttons, forms, and navigation.
- Body text should normally be 16 pixels or larger.
- Keep line length comfortable and avoid dense text blocks.
- Use no more than three font weights: 400, 600, and 700.

## 4. Logo direction

Use a simple text wordmark for the MVP:

**NiaGuide** in deep navy, with **Africa** in royal blue or warm gold.

A small compass, open-book, or quotation/source-marker symbol may appear beside the name. Do not spend development time on a complex logo.

## 5. Core interface components

- Top navigation with logo, Experts, How it works, About, and Sign in.
- Hero section with a simple explanation and **Explore experts** button.
- Expert cards with photograph or initials, name, field, topics, source count, and status.
- Expert profile header with disclosure clearly shown.
- Question form with example questions.
- Answer card with AI label, response, numbered citations, and feedback controls.
- Source panel with source title, date, link, and supporting excerpt.
- Evidence warning card for insufficient support.
- Simple admin side navigation and data tables.

## 6. Wireframe instructions

Codex should first create low-fidelity responsive wireframes as code or Mermaid/document diagrams for:

1. Landing page
2. Expert directory
3. Expert profile
4. Ask-and-answer page
5. Admin dashboard

After the project owner approves the layout, Codex should implement the polished interface. If time is too short, Codex may proceed with the design system above and include screenshots in the README.

## 7. Content tone

- Use simple English suitable for a university student.
- Never say “Talk to Joyce Daniels” or “Ask Joyce directly.”
- Say “Explore the approved knowledge collection” or “Ask the source-grounded assistant.”
- Never use the expert's first-person voice unless a passage is clearly presented as a short quotation with a source.
- Keep disclosures visible and understandable.

## 8. Example interface text

### Hero heading

**Find guidance grounded in African experience.**

### Hero description

Ask career and personal-development questions. Receive AI-generated answers based on approved materials from African leaders and experts, with sources you can check.

### Main call to action

**Explore experts**

### Question box heading

**What would you like to learn from this collection?**

### Question placeholder

**For example: How can I become more confident when speaking in public?**

### Source panel heading

**Evidence used for this answer**

### Feedback question

**Was this answer useful and well supported?**
